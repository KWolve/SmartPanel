# SmartPanel_HA 多屏拼接 使用说明书

> 适用产品：Z20 智能家居面板（480×480，SmartPanel_HA 工程）
> 版本：**v2.0（2026-09-27 晚）**｜编写依据：工程源码 + 两台真机（192.0.2.108 / .71）实测
> 相关设计文档：`docs/wall-linkage-design.md`（协议/算法设计）、`references/kb/z20-mi-vdec-channel-attrs.md`（解码通道口径）、`references/kb/video-wall-sync.md`（相位/验收口径）、`tools/video_wall/README.md`（切块工具）、`docs/整机说明书.md` §3.3（校时）
> **v2.0 新增：一组多视频轮播（`playlist.json` v2）+ 组名自定义**（固件 2026-09-27 22:1x 落地）→ 见 §5

---

## 1. 功能是什么

把 **≤4 台**同型号面板排成一堵墙（单行横排 `1xN`），播放**同一段（或同一条轮播清单里的）视频**，
每台只显示属于自己的那一格，画面**同帧同步**（实测相位差 ≤3 ms，判据 ≤40 ms = 1 帧）。

- **长什么样**：屏保状态下，整墙各机播放同一素材，本机显示"第 N 格"；错位用手指触摸任意屏 → 退出屏保回主页（拼接暂停）。
- **不依赖服务器**：同网段 UDP 广播自组网（无需 MQTT、无需云端）。
- **素材**：一组 = 一个目录，里面可以放**一段视频**（旧布局）或**多个视频轮播（v2，各 clip 长短不限）**，
  按"本机序号"分发给各机本地存储；**组名 = 目录名，可自定义**（见 §5）。

---

## 2. 使用前提（不满足则不同步）

| 前提 | 要求 | 不满足的后果 |
|---|---|---|
| 网络 | 同网段、互通、允许 UDP 广播（交换机关闭"广播风暴抑制/客户端隔离"） | 收不到 epoch → 各自轮播，不同步 |
| 时间 | **各机都已完成 NTP 校时**（本机：默认网关 + 内置公网兜底，见 `docs/整机说明书.md` §3.3） | 相位随钟差漂移，越播越错（钟差大时两台画面可差 ≈10 帧） |
| 型号/分辨率 | 同型号、同分辨率、同安装方向（0° 或统一旋转角） | 画面切分对不上 |
| 素材 | **同一 clip 内**各机那一段 `seg_<本机序号>.mp4` **时长一致**（差异 ≤40 ms）；**不同 clip 之间可以长短不同** | 循环缝变大 / 末帧冻结 |
| 系统版本 | 两台固件一致（`/res/lib/libzkgui.so` md5 相同） | 行为不一致、难以定责 |

## 3. 快速上手（5 步）

1. **准备素材**：用切块工具（`tools/video_wall/`，网页 `http://<PC>:8796/`，见 §6）生成组目录，再推到**每台**机器
   `/mnt/sdnand/wall/<组名>/` 下：
   - 旧布局（一段视频）：组目录下直接放 `seg_1.mp4 … seg_N.mp4`
     （例：组 `zksw-wall`、2 台 → `108` 上放 `seg_1.mp4`、`71` 上放 `seg_2.mp4`）；
   - **v2 多视频轮播**：`python split_wall.py group --in a.mp4 --in b.mp4 --cols 2 --group-name <组名> --out-dir out/g1`
     → `out/g1/{playlist.json, wall.json, c1/seg_1..N.mp4, c2/seg_1..N.mp4}`（见 §5、§6）。
2. **进设置**：主页右上「齿轮」→「设置」→ 滑到底 →「**多屏拼接**」行。
3. **逐行配置**（点一行切换一个值，**立即落盘**）：
   ①拼接联动=开启 → ②组名（两台**必须相同**）→ ③本机序号（**每台唯一**）→ ④排布（总台数）
   → ⑤角色（**序号 1 建议设主机**）→ ⑥播放内容（只读显示 `K 段 · 总 X.Xs`，见 §4.6）
4. **确认两台数值一致/互补**，点「保存」→「返回」。
5. **等屏保自动进入**（或手动息屏再唤醒触发）→ 两台应同步播放同一画面。

> 多屏拼接页底部状态卡会直接显示状态：`状态：拼接中（本机 seg_2/2 · K 段轮播 · 主机）`；未启用时显示 `状态：未开启（屏保按原清单轮播）`。

## 4. 参数逐项说明

### 4.1 拼接联动（开关）
- 取值：开启 / 关闭（点击切换）。
- 关闭后本机**完全回到旧行为**：屏保按原素材清单轮播，不参与拼接。
- 键：`sp_wall_en`（bool）。

### 4.2 组名
- 取值：点一下在 `/mnt/sdnand/wall` 下**真实存在的组目录之间循环**（当前值不在列表里时排在最前）。
- **组名怎么来的 = 目录名**：切块工具建组时填的名字（工具侧允许中文，会自动清洗路径非法字符），
  设备端就是 `/mnt/sdnand/wall/<组名>/` 这个目录 —— **换个组名不用改固件、不用改代码**。
- 盘上一个组目录都没有时，状态行会明确提示 `未找到组目录（请先用切块工具生成）`——别对着"拼接中"猜为什么没画面。
- **同组各机必须完全一致**；不同组互不干扰（同一网段可并存多组）。
- 键：`sp_wall_group`（string，默认 `zksw-wall`）。

### 4.3 本机序号
- 取值：`1 … 总台数` 循环（点击 +1，超过总台数回到 1）。
- **每台必须唯一**，决定本机播放哪个切片（`seg_<序号>.mp4`）以及墙上的格子位置。
- 键：`sp_wall_idx`（int，默认 1）。

### 4.4 排布（总台数）
- 取值：`2 → 3 → 4 → 2` 循环（显示为 `1x2 / 1x3 / 1x4`，即单行横排）。
- 改变后若本机序号超出，会自动收敛到新台数。
- 键：`sp_wall_n`（int，默认 2）。

### 4.5 角色
- 取值：主机 / 从机 切换。
- **主机**：唯一的"时间权威"，周期性广播本轮起点 epoch（秒级心跳 1 次 + 进屏保时被"点播"秒回）。
- **从机**：跟随主机 epoch 对齐相位。
- **约定：组内序号 1 的机器设为主机**；两台都设主机 → 互相打架，千万别这么配。
- 键：`sp_wall_role`（int，1=主机，0=从机，默认 1）。

### 4.6 播放内容（原「片段时长」行）
- **v2 起这一行改叫「播放内容」**，显示本组清单里的内容概要：
  - 多视频组（有 `playlist.json`）：`K 段 · 总 X.Xs`，K = 组内 clip 数、总 = 一轮轮播时长；
  - 旧布局（无 `playlist.json`）：`1 段 · 10.0s`（= 同一段循环）。
- 该行**只显示、不改值**（点击不改变数值）。要换内容/时长 → 换素材组或重新出包，用切块工具（§6）。
- 底层键仍是 `sp_wall_seg_ms`（int，默认 30000）：单 clip 模式下必须等于素材真实时长；
  **多 clip 模式下时间轴以 `playlist.json` 的 `total_ms` 为准**，`sp_wall_seg_ms` 只作单 clip/兜底口径。
- ⚠️ 只有单 clip 模式才校验"素材时长 = `sp_wall_seg_ms`"（不符日志 `WARN wall[sp]: content … != period …`，按周期截断/冻结末帧）；**多 clip 模式不再按周期截断**。

## 5. 多视频轮播（v2：一个组 = 多个视频 + 组名自定义）

> 2026-09-27 晚新增（**固件 + PC 工具均已上机跑通**）。v1 的"一组一段视频"是它的特例，旧布局继续兼容。

### 5.1 两种模式对照

| 模式 | 组目录里有什么 | 时间轴周期 | 什么时候用 |
|---|---|---|---|
| **单 clip（旧布局，继续兼容）** | 直接放 `seg_1..N.mp4` + `wall.json`（**没有** `playlist.json`） | 一段时长（`sp_wall_seg_ms`） | 只循环播一段 |
| **多 clip（v2，本版）** | `playlist.json` + `c1/seg_1..N.mp4` + `c2/…` + … + `wall.json`（v1 兼容壳） | **一轮总时长** = Σ 各 clip 时长 | 一条墙上要轮播多个视频 |

判定：**组目录里有合法的 `playlist.json` 就走多 clip**，否则退回单 clip（口径与 v1 完全一致）。

### 5.2 磁盘布局

```
/mnt/sdnand/wall/<组名>/
├── playlist.json                  ← v2 清单（固件必读；有它才进多 clip 模式）
├── wall.json                      ← v1 兼容壳（保留写，给旧读者/排查用）
├── c1/seg_1.mp4 … c1/seg_N.mp4    ← 第 1 个视频切成 N 段（每段 480×480）
├── c2/seg_1.mp4 … c2/seg_N.mp4    ← 第 2 个视频（段数同为 N，时长可不同）
└── …（c3、c4 … 任意个）
```

### 5.3 `playlist.json` v2 字段（工具 ↔ 固件的唯一契约）

```json
{
  "version": 2,
  "group": "fish-mario",
  "n": 2,
  "cols": 2,
  "total_ms": 245920,
  "clips": [
    {"name": "c1", "dur_ms": 10040, "segments": [
        {"index": 1, "file": "c1/seg_1.mp4", "dur_ms": 10040},
        {"index": 2, "file": "c1/seg_2.mp4", "dur_ms": 10040}]},
    {"name": "c2", "dur_ms": 235880, "segments": [
        {"index": 1, "file": "c2/seg_1.mp4", "dur_ms": 235880},
        {"index": 2, "file": "c2/seg_2.mp4", "dur_ms": 235880}]}
  ]
}
```

| 字段 | 含义 |
|---|---|
| `version` | 恒 `2` |
| `group` | 组名（= 目录名；工具侧已清洗路径非法字符） |
| `n` | **组内 clip 数**（轮播几个视频）；固件对 `n != len(clips)` 容错，**一律以 `len(clips)` 为准** |
| `cols` | **每个 clip 的段数 = 屏数 N** |
| `total_ms` | 一整轮轮播时长 = Σ `clip.dur_ms` |
| `clips[]` | 按**轮播顺序**排；`name` = 子目录名（与 `file` 前缀一致） |
| `clip.dur_ms` | 该 clip 的播放时长（同一 clip 内各段等长 ⇒ 等价于单片时长） |
| `segments[].index` | 从 1 连续到 `cols` |
| `segments[].file` | **相对组目录**的路径（如 `c1/seg_1.mp4`） |
| `segments[].dur_ms` | 该段时长 |

- ⚠️ **`n` 是 clip 数、不是屏数**（屏数以设备 `sp_wall_n` 与 `segments` 长度为准）——工具与固件已按此对齐，别混。
- 固件**以本地 `playlist.json` 为准**：与主机广播的 `total_ms` / `clips` 不一致只打 `WARN`，**绝不停播**。

### 5.4 播放时长没有约束（各 clip 可长短不一）

- **各 clip 时长可以完全不同**：实测组 `fish-mario` = 鱼缸 **10.04 s** + 马里奥 **235.88 s**，一轮 **245.92 s**；
- 但**同一个 clip 内**、各机那一段必须**等长、编码参数完全一致**（这是能对齐的前提，切块工具已保证）；
- 播到 clip 末尾时播放器**直接 reopen 下一个 clip 的文件**（不 seek、轮末不留空档），最后一个 clip 播完回到第一个。

### 5.5 同步原理（多 clip 下口径不变）

```
组时钟   g   = 本机组内墙钟 − epoch          （epoch = 主机广播的轮起点）
轮内位置 pos = g mod total_ms
→ 由 pos 定位到「第几个 clip + clip 内偏移」，按主机整边界起播
```

- 同一 `epoch` + 同一公式 = 同一时刻同一帧；UDP 抖动/心跳相位差不进相位；
- 主机广播协议**向后兼容扩展**：`wall|<组名>|<t0_ms>|<seg_ms>|<n>|<pub_ms>|<clips>|<total_ms>`
  （**末尾追加两个字段**，老从机只读前 6 段，不受影响）；
- **实测（108 / 71，组 `fish-mario`）**：两台轮播切换/回卷时刻 **Δ = 0~1 ms**、同帧；
  画面块度中位 **1.07 / 1.00**（判据 ≤1.2）；`dropGop=0`（无丢 GOP、无空档）。

### 5.6 组名自定义

- 组名 = `/mnt/sdnand/wall/` 下的**目录名**，起什么名都行（工具侧允许中文，自动清洗路径非法字符）；
- 设置页「**组名**」行点一下 → 在盘上**真实存在的组目录之间循环**（当前值不在列表则排最前）；一个都没有时给提示；
- 同组各机组名必须一致；同网段可并存多组互不干扰。

### 5.7 设备设置页怎么看（v2 文案）

| 行 | v2 显示（例） | 说明 |
|---|---|---|
| ②组名 | `fish-mario` | 在盘上真实存在的组目录之间循环 |
| ⑥播放内容 | `2 段 · 总 245.9s` | 读本组 `playlist.json`：K = clip 数、总 = 一轮时长；**旧布局**显示 `1 段 · 10.0s` |
| 状态行 | `状态：拼接中（本机 seg_2/2 · 2 段轮播 · 主机）` | 多 clip 时带 `K 段轮播` |
| 状态行（异常） | `状态：未找到组目录（请先用切块工具生成）` | 盘上没有组目录时的明确提示 |

## 6. 素材准备要点

| 项 | 要求 |
|---|---|
| 路径 | 单 clip：`<设备>/mnt/sdnand/wall/<组名>/seg_<本机序号>.mp4`　多 clip：`<设备>/mnt/sdnand/wall/<组名>/<clip 名>/seg_<本机序号>.mp4` |
| 命名 | `seg_1.mp4`、`seg_2.mp4` …（序号与"本机序号"一致）；clip 子目录名由工具生成（`c1..cK`，可改名） |
| 编码 | H.264（本机硬件解码），分辨率不超过屏幕（480×480 竖屏请按实际方向切） |
| 时长 | **同一 clip 内各机严格等长**；单 clip 的总时长 = `sp_wall_seg_ms`；多 clip 一轮 = Σ 各 clip 时长 |
| 切法 | 整墙画面按台数等宽切分（`1xN` 横排 → 沿 X 等切）；**框外画面丢弃、不补黑边**（补黑会让相邻屏黑边连成黑带） |
| 参数一致 | **各段参数完全一样**（编码/像素格式/帧率/关键帧间隔），各屏才不会各行其是 |
| 建议 | 段首放 I 帧（本机支持 I 帧追赶，但段首 I 帧起播更干净） |

### 6.1 用工具一条命令出「多 clip 组」

> 工具在 PC 侧（`tools/video_wall/`，只依赖 `ffmpeg` / `ffprobe`；完整说明见该目录 `README.md`）。

```bash
# ① 网页（推荐，所见即所得）：http://<PC_IP>:8796/
#    导入多个视频 → 逐个点进「组的视频队列」（= 轮播顺序）→ 对每个 clip 摆绿框
#    → 填组名 → 「导出整组」→「一键分发整组」

# ② 命令行（多源成组；每个 clip 各自摆框、长短不限）
python split_wall.py group --in a.mp4 --in b.mp4 --cols 2 --group-name fish-mario --out-dir out/g1
#    产物：out/g1/{playlist.json, wall.json, c1/seg_1..N.mp4, c2/seg_1..N.mp4}

# ③ 校验（段数/参数一致/首帧 IDR/总时长）
python split_wall.py verify --dir out/g1/c1
python selftest_group.py

# ④ 分发到各机（整组递归推送；--dry-run 只看不推、**不碰设备**）
python distribute.py push --group-dir out/g1 --group fish-mario \
       --devices 192.0.2.108=1,192.0.2.71=2
python distribute.py push --group-dir out/g1 --group fish-mario \
       --devices 192.0.2.108=1 --only-mine      # 只推本机要播的那一段，省设备空间
```

- **`--only-mine`**：设备 `/mnt/sdnand` 只有 **75 MB**，整组（尤其多 clip + 长视频）容易塞满；
  加了它每台**只存自己要播的那一段** + 两份清单（`playlist.json` / `wall.json`），其余段不占空间。
- 组名在导出那一行填（默认取第一个源片名，非法字符自动清洗；工具侧组名允许中文，clip 名限 ASCII）。

## 7. 工作原理（便于排障）

> 多 clip 的时间轴口径（`pos = g mod total_ms` 定位到第几个 clip）见 **§5.5**。

1. **主机定期广播 epoch**（本轮循环的墙钟起点毫秒）；从机收到即知"整墙现在播到哪"。
2. **对齐全靠墙钟**：每段播完**不立刻续播**，而是各自算 `nextBoundaryMs()`（下一个整边界的**绝对墙钟**）→ 本地精等到点再起播；两台算出的绝对时刻相同 → 天然对齐（不靠互发"开始"信令）。
3. **进屏保快速对齐**：从机进屏保时广播一次 `wall?|<组>`，主机收到**立刻补发 epoch**（等待从 1 s 心跳压到毫秒级）→ 从机**直接 seek 到当前相位对应的画面**，不必等下一轮。
4. **两段式起播**：提前约 160 ms 先 `stop()` 拆掉上一段（耗时 110~180 ms 且各机不一），到整边界只做冷启动 `play()`（开销 0~6 ms）→ 这是相位能收敛到 1 帧内的关键。
5. **自校准**：把实测"起播-目标"偏差以死区 ±10 ms、限幅 ±30 ms 反馈进下一轮。
6. **失联兜底**：>10 s 收不到 epoch → 本机回退普通屏保轮播（不影响其他台）。
7. **守卫**：若收到的 epoch 落在"未来 >1 h"（典型是开机组网未授时/脏值），**拒绝起播**并打日志 `clock_insane(...)`，避免整墙错位。
8. **平台差异**：Z20 上播放走**本机自建硬解**（MI VDEC + MI DISP）；easyui 自带 zkmedia 在 Z20 是**软解**（FFmpeg），不参与拼接。

## 8. 高阶参数（`/data/preferences.json`，改完重启应用生效）

| 键 | 默认 | 用途 / 取值建议 |
|---|---|---|
| `sp_wall_en` | false | 拼接总开关（true/1 均识别为开） |
| `sp_wall_group` | `zksw-wall` | 组名（同组一致） |
| `sp_wall_idx` | 1 | 本机序号（唯一，1…N） |
| `sp_wall_n` | 2 | 总台数 2~4 |
| `sp_wall_role` | 1 | 1=主机 / 0=从机 |
| `sp_wall_seg_ms` | 30000 | 片段时长（ms），须等于素材时长 |
| `sp_wall_engine` | 0 | **播放内核**：`0`=v4（easyui 播放器 + 整边界两段式，实测 |Δ|≤19 ms）；`1`=simple（自读包 + I 帧追赶 + 墙钟控速，当前现场值） |
| `sp_wall_join` | true | 进屏保"先对齐再跳画面"开关（`0`/`false` 均关闭，回到已验证的旧行为） |
| `sp_wall_join_to_ms` | 5000 | 进屏保等 epoch 的超时（ms），超时即退回轮播 |
| `sp_wall_lead_ms` | 0 | 起播提前量（补偿引擎起播延迟，一般不用动） |
| `sp_wall_vdec_ch` / `sp_wall_disp_ch` | 1 / 1 | MI 通道对；起播失败会自动回退 `(1,0)→(0,1)→(0,0)` |
| `sp_wall_rotate` | 0 | 本机画面旋转角（多台必须统一处理） |
| `sp_wall_clock_wait_ms` | 30000 | **时钟可信门**：本机墙钟 < 2024-01-01（掉电后 RTC 空 / 未校时）时先等 NTP，最长等这么久；超时仍不可信 → WARN 后按本机钟继续（靠钟差兜底） |

> 关闭拼接回退旧行为：把 `sp_wall_join` 设 `false`（或 0）→ 停/启一次应用即可。

## 9. 常见问题排查

| 现象 | 先查什么 | 处置 |
|---|---|---|
| 两台各播各的、不同步 | ①两台网络/组名是否一致 ②是否同 NTP 源 ③`sp_wall_role` 是否**只有一台**主机 | 改配置 → 停/启应用；仍有问题看日志有没有 `wall: start target=…` |
| 画面错位半屏/花屏 | 本机 `seg_<序号>.mp4` 是否放对；设备解码通道块度 | 抓帧算块度（见 §11）；确认解码通道属性为 2 MB / RefFrmNum=16 / NORMAL |
| 播放卡住、只出一帧 | 是否 `content != period` 警告（**仅单 clip 模式**：素材时长与 `sp_wall_seg_ms` 不符） | 对齐素材时长或改 `sp_wall_seg_ms`；多 clip 模式不按周期截断 |
| 进屏保半天不同步 | 主机是否被"点播"到（日志 `wall?` / `ping|pong`） | 检查 UDP 广播是否被交换机拦截 |
| 一直 `clock_insane FAILED` 不播 | 本机/主机时钟是否被授时 | 等 NTP 同步或临时校正；该守卫只拦"未来 >1 h"的脏 epoch，长 uptime 不再误杀 |
| 播放几小时后停了 | 旧版本 `|now-epoch|>1h` 误杀（已修） | 升级到当前版本；新逻辑只查"epoch 在未来" |
| 升级/推包后画面异常 | 应用重启时机（运行中重启可能卡 MI 驱动） | 断电重上电整板重启恢复；避免连续反复重启 |
| 设置页「多屏拼接」行点不进去 | 该行装饰层是否吃掉了按下事件（已修） | 升级到当前版本 |
| **两块屏画面差一截（差几帧到十几帧）** | **先看两台校时/钟差**：①两台是否都已完成 NTP（设置页时钟状态 / 日志 `ClockManager: synced via …`）②面板 **RTC 是空的、掉电不保时**，开机不校时两台就会差 0~1 s | 等 NTP 同步后再进屏保；日志看 `skew`（固件取**近 5 次中值**、只丢 \|skew\|>120 s 的脏样本）。判据：单台绝对误差 ≤100 ms、两台互差 ≤50 ms —— **待验证数据（占位）**，见 §12 |
| 「组名」行循环不到我建的组 / ⑥显示 `未设置` | ①组目录是否真在 `/mnt/sdnand/wall/` 下（大小写一致）②有没有推上去 ③`playlist.json` 是否随组推送了 | 用切块工具重新推送**整组**（含 `playlist.json`）；状态行会提示"未找到组目录" |
| 推上去没变化 | **先查 `/mnt/extsd/EasyUI.cfg`** 的 `startupLibPath` 是否在劫持（加载了 SD 卡上的旧库/旧界面） | 改回或删掉该文件后重启应用（详见 `docs/整机说明书.md` §7.2） |

## 11. 验收判据（可复核）

| 项 | 判据 | 复核方法 |
|---|---|---|
| 相位同步 | 两台 `|Δnow|` **≤40 ms**（1 帧），连续多轮 | 两机 `logcat` 抓 `wall[sp]: sync cyc=… pts=… want=… now=…`，按同一 `cyc/pts` 配对求差 |
| 多 clip 轮播切换/回卷 | 两台切换（含回卷到第 1 个 clip）时刻 **Δ ≤1 ms**、同一帧 | 两机日志 `wall[sp]: playlist clip-switch …` / `playlist wrap …` 配对求差（实测 0~1 ms） |
| 轮播无空档 | `dropGop=0`（GOP 不丢、轮末不空） | `reopen(...)` 行里的 `dropGop` / `dropSize` 计数 |
| 校时（**待验证**） | 单台绝对误差 **≤100 ms**、两台互差 **≤50 ms** | 两机 `logcat` 抓 `ClockManager: synced via …` 与 `skew`（近 5 次中值）——**改后数字待补** |
| 画面质量 | 设备抓帧"块度" **≤1.2**（源帧基准 1.05~1.25） | 设备端 `zkshot <out.raw> vdec <chn> 0` 抓 YUV，按 16 像素边界算块度 |
| 版本一致 | 两台 `/res/lib/libzkgui.so` md5 相同 | `md5sum`（设备无该命令时 `adb pull` 后本机算） |
| 运行状态 | `getprop sys.zkapp.state` = `running` | — |
| 资源一致 | 两台 `/res/ui/*.ftu` 与出包一致 | `adb pull` 后比对 md5 |

实测基线（2026-09-27，2/3 台配置）：相位 **max 3 ms**、块度 **1.08~1.17**。

## 12. 已知限制

- 「设备倒装」的视频方向**无法截屏核验**（视频层不在 `/dev/fb0`）→ 首次上机请用相机拍屏确认；若现场发现视频未跟随旋转，处置见 §13 备注（改走解码/渲染侧旋转或素材预旋转）。
- 排布仅支持**单行横排**（`1xN`），暂不支持 2×2 等二维排布。
- 多 clip 组**导出固定 25 fps**（源 24/30 fps 会重采样；同一 clip 内各段一致，不影响相位对齐）。
- 源片**自带 letterbox 黑边不会自动去掉**（切块工具不做黑边检测；需要时把绿框放大到黑条出框）。
- 组名虽已可自定义，但**必须与设备上的目录名一致**；改组名 = 换目录名（工具重推或手工改名）。
- 设备 `/mnt/sdnand` 只有 **75 MB** → 多 clip 大组要配 `--only-mine` 分发（每台只存自己那段）。
- **NTP 校时改造（v6）的"改后实测数字"待验证**（另一条线正在给 108/71 推固件验证：判据 = 单台绝对误差 ≤100 ms、两台互差 ≤50 ms）——本文档相应格子为**占位，未编数字**。
- 拼接在**屏保**中生效；面板正常操作时（主页/设置）拼接暂停。
- 主从角色需人工设置，目前无自动选举。
- 从机跨机改配置后需停/启一次应用（或等屏保重新进入）才生效。

## 13. 设备倒装（整屏 + 视频 180°，2026-09-27 钟工）

**用途**：面板被**倒装**安装在墙上（上下颠倒）时，一次点击把 UI + 触摸 + 视频全部转 180°，不用改工程、不用换素材。

**位置**：设置页 →「系统」组 → **设备倒装**（在「版本信息」上一行）。

| 项 | 说明 |
|---|---|
| 取值 | `开启` / `关闭`（点击即切换、**立即生效**、掉电保持） |
| 键 | `sp_flip180`（bool；`true`/`1` 都认，默认关） |
| UI | `CONFIGMANAGER->setScreenRotate(180)` + `setTouchRotate(180)`（easyui 原生旋转：UI 软件 180° 翻转 + 触摸坐标同角度映射） |
| 视频 | `MI_DISP_SetVideoLayerRotateMode(0, {eRotateMode=2})`（MI DISP **图层级**旋转，对本板两条播放引擎都生效：simple `WallPlayer` 与 v4 `ZKVideoView` 都在 DISP 层 0，只是输入端口不同） |
| 开关顺序 | 先落盘 → 停播放器（**MI 图层属性不能在播放中改**）→ 转 UI/触摸 → 转视频层；播放器由屏保页心跳自动按新旋转重起 |
| 开机 | `mainLogic::onUI_init` / `onUI_show` 按 `sp_flip180` 重新应用（不会出现"设置了但重启没转"） |
| 拼墙影响 | **无**：两台相位差、块度与开启前一致（见 §11 判据；本次实测 |Δpts| max 0 ms、块度 1.04~1.18） |

**为什么不用"两套 ftu"**：面板是 480×480 **正方形**，180° 不需要换布局（老 easyui 也没有 relayout）。

**现场核对视频方向**：视频层不在 `/dev/fb0`，**截屏只能拿到 UI 层**。设备侧可读 `/proc/mi_modules/mi_disp/mi_disp0` 的
`LayerId 0 … rotatemode` 字段（开= `rotate_180`，关= `NONE`）作为客观自证；**视频画面方向请用相机拍屏确认**。
