# 多屏拼接联动（同一时刻同一帧）· 主机设计

> 钟工 2026-09-25 口径：1×2 / 1×3 / 1×4 多种排布；**做主机设计**；互联网 NTP 并把**网络延迟补偿**进去，
> 兜底走**局域网广播**；**失联时回到默认屏保视频**；**屏保资源与联动资源分开控制**（联动资源先手工放 SDNAND 独立目录）。
> 目标：N 台面板同时显示各自片段 → 拼成大画面，肉眼/相机看是"一整块"。

---

## 1. 验收口径（先定标尺）
| 项 | 目标值 | 判定方式 |
|---|---|---|
| 帧对齐误差 | **≤ 1 帧**（25fps → 40ms；30fps → 33ms） | 两台同拍一帧截图，比测试片上的**帧号**（`sample` 命令生成的片子自带 5 位帧号 + 时间码） |
| 稳态漂移 | 不累积（纠偏后回到 ≤1 帧） | 连续观察 ≥3 个循环，记录偏差日志 |
| 起播对齐 | 起播瞬间 ≤2 帧 | 起播时刻日志 + 截图帧号 |
| 失联 | ≤ 10s 内退回默认屏保 | 断网/断 broker 测试 |

> 说明：**绝对 0 帧差跨设备做不到**（解码起播与 seek 都有物理延迟）；工程目标按上面 ±1 帧。

## 2. 角色与拓扑（主机设计）
```
        ┌──────────── 组 wall-A ────────────┐
        │                                   │
   [主机 MASTER]  ←── epoch/配置（MQTT retained + UDP 兜底） ──→  [从机 SLAVE 2..N]
        │  seg_1                                                      │ seg_2..seg_N
   墙钟时间轴(NTP)                                             墙钟时间轴(NTP)
```
- **主机**：唯一权威。负责 ① 组配置（组名/排布/段数/段时长/版本）② **epoch**（本轮循环的墙钟起点，NTP 时间）
  ③ 周期性心跳（从机据此判失联）。主机自己也播 `seg_1`，不是只发命令。
- **从机**：只跟随。收 epoch/配置 → 对齐 → 播自己的 `seg_<idx>` → 周期性自查相位并发漂移上报（可选，便于排障）。
- **本机序号**：= 段号（1..N），面板按序号取 `/mnt/sdnand/wall/<组名>/seg_<idx>.mp4`。
- 主机可配置（默认：组内序号 1 的那台；也可在设置页手动指定"本机为主机"）。
- **单机自测模式**：主机同时扮演从机（本机序号 = 段号），便于 1.108 单台模拟。

## 3. 时间轴（NTP + 网络延迟补偿 —— 您指定的核心）
### 3.1 NTP 校时（互联网源 + RTT 补偿）
- 客户端四时间戳：`T1` 本机发送、`T2` 服务端收到、`T3` 服务端发出、`T4` 本机收到
  - `offset = ((T2 − T1) + (T3 − T4)) / 2`（本机相对参考时钟的偏差）
  - `rtt    = (T4 − T1) − (T3 − T2)`（往返净延迟）
- **补偿与筛选**：拿多台服务器/多次取样，**丢弃 RTT 过大样本**（建议 > 100ms），其余取 **中位数** offset；
  把 offset 写回系统时钟（`settimeofday`/`TimeHelper::setDateTime`），并把 **offset/RTT 记录到状态**供 UI 显示。
- **校时时机**：① 开机；② **进入拼接播放前强制校一次**；③ 周期（建议 10~15 分钟）；④ 每轮循环开始时读一次
  offset 估算漂移（不强制重校）。
- ⚠️ 公网 NTP 单次偏差常见 10~50ms，**仅靠公网 NTP 很难稳进 ±1 帧** → 因此：
  - 主机的 epoch 与从机的时间判断都基于 **已补偿 offset 的本地时间**；
  - 且引入下面 3.3 的**闭环纠偏**兜住残差（这是能不能进 ±1 帧的关键）。
  - 若后续允许在局域网放一个 NTP 服务（PC/WSL 上 `chrony/ntpd` 即可），精度会显著更好（列为可选项）。

### 3.2 epoch 与相位
- 主机发布（**MQTT retained**）：`wall/<组名>/epoch = {t0_ms, seg_ms, layout, total, ver}`，`t0_ms` = 对齐后的墙钟毫秒
- 从机（以及主机自己）计算：`phase = (now_ms − t0_ms) mod seg_ms`；期望播放位置 `expect = phase`
- **起播对齐**：不立刻播，而是等**下一个整边界**：`wait = seg_ms − phase` → 到点 `play(seg, 0)`；
  这样多台在同一个边界同时从 0 帧起播（误差 = 各自起播延迟差）。
- **循环**：每段播完自然回到 0 帧；下一轮的边界仍由 epoch 推导（`t0 + k*seg_ms`），
  因此**不需要每轮重新同步**，天然抗漂移累积（只要时钟不漂）。

### 3.3 闭环纠偏（把误差压到 ±1 帧）
- 每秒（或每 250ms）计算 `expect = (now − t0) mod seg_ms`，与**实际播放位置**比较（`getDuration()` 之外，
  需要播放位置：可用"本段起播墙钟 + 已播时长"自算，或播放器提供的位置接口；落地时按 Z20 API 实测选择）
- 偏差 `|expect − actual|`：
  - ≤ 半帧（20ms@25fps）→ 不动
  - > 半帧且 ≤ 100ms → `seekTo(expect)` 微调
  - > 100ms 或连续 3 次不收敛 → 放弃本段，**停到下一个整边界重新起播**（干净重对齐）
- 纠偏节流：同一段内最多纠 2 次，避免"seek→解码波动→再 seek"来回抖。

## 4. 通道与兜底（您指定）
| 优先级 | 通道 | 用途 | 备注 |
|---|---|---|---|
| 1 | **MQTT**（现有 broker，EMQX） | epoch/配置（retained）+ 心跳 | 已通；主机发布，从机订阅；retained 让后加入的从机立刻拿到 |
| 2 | **局域网 UDP 广播** | 同上（兜底） | 复用 `LocalLink` 现有广播心跳（UDP 8899）；broker 不可用时主机每 1s 广播 epoch |
| — | 失联判定 | 从机 > 10s 收不到 epoch/心跳 → **退回默认屏保视频**（正常轮播），拼接页显示"失联" | 不黑屏、不卡死 |

## 5. 资源与目录（联动 / 屏保分开）
```
/mnt/sdnand/wall/<组名>/seg_1..N.mp4   ← 联动片段（PC 端 tools/video_wall 切块产出）
/mnt/sdnand/wall/<组名>/wall.json      ← 清单：段序/分辨率/fps/时长/md5
/mnt/sdnand/video/  /mnt/sdnand/album/ ← 屏保资源（轮播清单，含小程序上传）——与联动互不干扰
```
- 拼接模式下**屏保页不参与轮播**，只播本机片段；退出拼接/失联 → 回到屏保轮播（今天的清单刷新修复保证新素材照常加入）。
- 资源先手工 adb push（钟工口径）；面板侧只读、不改写。

## 8. 风险 / 待确认
1. **Z20 播放器是否有 `SIMPLE_PLAYER_SYNC` / `ZKMEDIA_VIDEO_HOLDFRAME` 同级能力？**（tag 电子价签量产的同步是播放器层的）
   → 需厂家/沛哥确认；若有，应用层纠偏可简化甚至省掉。
2. **起播/seek 实测延迟**：480×480 H.264 在 Z20 上的起播延迟与 seek 精度要真机测（决定纠偏阈值与能否进 ±1 帧）。
3. 播放位置读取接口：若 `ZKVideoView` 无"当前位置"接口，则用"起播墙钟 + 计时器"自算（本工程已有 tick 计时基建）。
4. 音频：多段同时出声会互相盖 → 默认只让一段带音轨（工具 `--audio-index`），或全部静音。
5. 公网 NTP 精度不足时的备选：局域网 NTP/主机授时（列为可选项，您定）。
